# Evolv screening counts → Excel

The Cloudflare Worker `evolv-counter` is configured to visit **https://evolv.com/** every 12 hours and store both displayed totals in **Cloudflare D1**. A protected download generates **evolv-screening-counts.xlsx** from the current history. No R2 bucket or Microsoft 365 account is required.

**Verified limitation, September 28, 2026:** Evolv returned HTTP 403 to all three Cloudflare browser attempts. Hosting and private downloads can operate, but automated collection is currently blocked. A manually observed baseline is explicitly labeled `interactive_browser`; it is not evidence of a successful automated run. Supported next steps are Evolv-approved access or an approved data feed.

**Report page:** [Open the private Excel report](https://evolv-counter.alatimore06370.workers.dev).

Open that page, enter the private download access key, and select **Download Excel**. The page sends the key in an Authorization header and does not save it in browser storage or a URL.

## Schedule and meaning

Cron `0 */12 * * *` attempts collection at **00:00 and 12:00 UTC**. In New York this is 8 a.m./8 p.m. during daylight time and 7 a.m./7 p.m. during standard time. Successful collections add durable rows. The protected manual trigger uses the same Cloudflare browser, so it is subject to the same 403 restriction.

These are the **animated numbers displayed on Evolv's homepage**, not independently verified device-level records. The homepage script inspected on September 28, 2026 advances both counters at 5 units per second from source anchors and refreshes the source every 300 seconds. The workbook separates displayed totals, source anchors, and their UTC timestamps.

The automated collector waits for the page's `awss_counter_series` POST, validates its response, and confirms the display uses those anchors. It never falls back to cached HTML `data-value` attributes. Missing, stale, malformed, or blocked data fails without inserting zeros. The JSON schema was inferred from the site script; a successful Cloudflare collection must be verified before relying on the schedule.

Each row's `collectionMethod` is `cloudflare_browser` for automatic collection or `interactive_browser` for a manually captured display reading. Source anchors and their timestamps are blank/null when unavailable for an interactive reading. These missing values are never replaced with invented anchors, zeros, or dates. The initial interactive baseline is added directly through authenticated database administration; there is no public import endpoint.

The interactive baseline observed at **2026-09-28 15:13:39.140 UTC** contained **5,130,323,691 people** and **32,756,288 bags**. Its source feed anchors were not captured, so those cells remain blank. This is one observed snapshot, not a successful Cloudflare collection.

## Endpoints

All paths below use `https://evolv-counter.alatimore06370.workers.dev`.

| Request | Authorization | Result |
| --- | --- | --- |
| `GET /` | None | Access-key form for Excel download |
| `GET /health` | None | Worker availability only, not data freshness |
| `GET /evolv-screening-counts.xlsx` | `Bearer DOWNLOAD_TOKEN` | Excel generated from current D1 history |
| `GET /data.json` | `Bearer DOWNLOAD_TOKEN` | Read-only history for future Streamlit use |
| `POST /admin/collect` | `Bearer ADMIN_TOKEN` | Collect immediately and await durable storage |

Use distinct random admin and download secrets of at least 32 characters. Keep them outside Git. The read key cannot collect data when the secrets are configured separately. Never put tokens in URLs. No CORS configuration is needed for a Streamlit server to call the JSON endpoint.

JSON fields are `schemaVersion`, `source`, `scheduleUtc`, `generatedAt`, `count`, `latest`, and `snapshots`. `latest` uses actual `observedAt`. Counts are numbers; timestamps are UTC ISO strings. Excel counts and dates are typed numeric/date cells.

An Excel request before the first observation returns 404. Database or workbook generation failures return 503. Manual collection failures return a short 502 JSON error; diagnostics are in Workers Logs. Existing D1 history remains safe if a later read or download fails.

## Local checks

Use Node.js 22.18 or later. Run `npm ci`, copy `.dev.vars.example` to `.dev.vars`, and replace both placeholders with distinct random secrets. Never commit `.dev.vars`.

```text
npm run types
npm run check
npm test
npm run dry-run
```

`worker-configuration.d.ts` is generated by Wrangler from bindings and local secret names. Tests use sample responses and fake services; they do not prove Evolv accepts Cloudflare's browser.

## Deploy and configure

`wrangler.jsonc` is configured for Worker `evolv-counter` and its D1 database. Browser Run and D1 must be available in the account. R2 is not used. Review current service usage limits and pricing before deploying into another account.

```text
npx wrangler login
npx wrangler d1 migrations apply evolv-screening-counts --remote
npm run types
npm run check
npm run dry-run
npm run deploy
npx wrangler secret put DOWNLOAD_TOKEN
npx wrangler secret put ADMIN_TOKEN
```

Supply each secret at its prompt. Deployment activates the cron; allow up to 15 minutes for trigger propagation. For a different account, first create its D1 database with `npx wrangler d1 create evolv-screening-counts` and update the account/database IDs in the configuration.

## Initial collection and download

With secrets already supplied as PowerShell session environment variables:

```powershell
Invoke-RestMethod -Method Post -Uri 'https://evolv-counter.alatimore06370.workers.dev/admin/collect' -Headers @{ Authorization = "Bearer $env:EVOLV_ADMIN_TOKEN" } -TimeoutSec 300
Invoke-RestMethod -Uri 'https://evolv-counter.alatimore06370.workers.dev/data.json' -Headers @{ Authorization = "Bearer $env:EVOLV_DOWNLOAD_TOKEN" }
Invoke-WebRequest -Uri 'https://evolv-counter.alatimore06370.workers.dev/evolv-screening-counts.xlsx' -Headers @{ Authorization = "Bearer $env:EVOLV_DOWNLOAD_TOKEN" } -OutFile 'evolv-screening-counts.xlsx'
```

Manual collection has no request body and waits for completion. Its `scheduledAt` is the real manual invocation time; each new call requests another observation. Confirm that JSON and Excel show the new `observedAt`. A downloaded file or chat attachment is a snapshot; download again for refreshed history.

Cron deliveries with the same scheduled timestamp are deduplicated. Failed collection leaves a gap rather than inventing a past reading. Check Workers Logs/Cron Events; do not assume a failed cron is automatically retried.

## Local integration test

Wrangler development uses local D1 and can launch a local browser. For Cloudflare's real browser, set `"remote": true` on the browser binding and authenticate; remote usage may incur charges.

```text
npx wrangler d1 migrations apply evolv-screening-counts --local
npm run dev
```

Use the local manual endpoint with `.dev.vars` credentials, or test cron in a second terminal:

```text
curl "http://localhost:8787/cdn-cgi/local/scheduled?format=json&time=1790596800000"
```

The fixed `time` identifies a test scheduled event in milliseconds; repeat it to verify deduplication. Actual observation time remains current. This testing route exists only in development.

## Files and maintenance

- `src/browser.ts`: validated collection, three attempts maximum, browser closed in `finally`.
- `src/parser.ts`: strict count and response validation.
- `src/job.ts` / `src/store.ts`: D1 history and cron deduplication. The retained post-collection hook is a production no-op because Excel is generated on download.
- `src/report.ts`: Excel generation.
- `src/index.ts`: landing form, protected manual/Excel/JSON routes, cron, and health.
- `migrations/0001_snapshots.sql`: initial database schema.
- `migrations/0002_collection_method.sql`: preserves existing rows and adds labeled interactive observations with nullable source anchors.

Response server time must be within 10 minutes of the collector clock; anchors must be no older than 24 hours. Selectors and source assumptions may require changes if Evolv changes its site. Exports are bounded to 10,000 observations, over 13 years at two per day; archive old rows before reaching this limit. No notification service is configured.
